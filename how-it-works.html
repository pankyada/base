How it works ​

Four short, animated walkthroughs — one per use case in Use Cases — showing what actually happens at runtime, beat by beat.

This page is deliberately narrower than the interactive architecture explorer. The explorer is a map: every layer, module, and file, with one generic 11-step request lifecycle. These films are narrative: what a specific scenario does, in order, with the real terminal states the runtime actually has — a budget abort, a contract rejection, an ACL denial, a durable deferred question. Read the explorer to see what exists. Watch these to see what happens.

Each film cites the real source files it depicts — nothing here is staged. Click a beat to jump to it; play/pause and a 2× speed toggle sit under each film. With reduced motion enabled, every film renders as a plain numbered list instead — nothing here requires the animation to be understood.

1. Coding assistant ​

A developer, in the loop the whole time. Every Bash call still asks first — watch the run pause and wait for a human.

Coding assistant

A developer in the loop the whole time. Follow one request from the TUI, through the transport boundary, down the agent loop, out to the model, and back through the approval gate before anything touches the shell.

  1. 1
    Go TUI → WS :7337

    You ask the TUI to fix a failing test. It opens a WebSocket to :7337.

    One process serves both WS and HTTP on one port; the TUI is a thin client with no agent logic of its own.

    tui/main.gosrc/server/index.ts

  2. 2
    WS :7337

    The upgrade is checked against the origin allowlist before it is accepted.

    WebSocket upgrades get no same-origin protection from the browser, so the server checks Origin itself.

    src/server/origin.ts

  3. 3
    WS :7337 → Profile registry

    The profile registry resolves which agent owns this connection — here, coding.

    src/profiles/schema.tsprofiles/coding.yaml

  4. 4
    Profile registry → Session

    A session is created: isolated per connection, with its own memory view.

    src/session/store.ts

  5. 5
    Session → Workflow router

    The workflow router triages the task and sends recon to the cheap model tier.

    cheap → balanced → frontier → critic. Escalation is earned by observed failure, never sized up front.

    src/workflow/profiles/coding.yaml

  6. 6
    Context projection → Agent loop

    Context projection turns the append-only ledger into a budgeted request.

    Tool results elide to restorable handles; the ledger itself is never rewritten.

    src/context/projection.ts

  7. 7
    Agent loop → Provider client

    The loop hands the projected conversation to the provider client.

    src/loop/agent-loop.ts

  8. 8
    Provider client → LLM API

    An OpenAI-compatible call goes out, retrying with backoff on transient errors.

    src/models/registry.ts

  9. 9
    LLM API → Agent loop

    Tokens stream back, along with a Bash tool call the model wants to make.

    src/loop/agent-loop.ts

  10. 10
    Agent loop → Tool registry

    The tool registry looks up the handler for that call.

    src/tools/registry.ts

  11. 11
    Tool registry → Conditional ACL

    The ACL resolves Bash to prompt — the one thing this profile always asks about.

    src/tools/acl.tsprofiles/coding.yaml

  12. 12
    Conditional ACL → Go TUI

    The run pauses and waits for you. Nothing executes until you approve.

    Shell commands are the highest-variance action a coding agent takes, so this gate is never skipped.

    src/server/index.tssrc/server/approval-mode.ts

  13. 13
    Built-ins → Hooks runner

    Approved: the command runs, wrapped by pre_tool and post_tool hooks.

    src/tools/builtin/src/hooks/runner.ts

  14. 14
    Hooks runner → Audit + undo

    The call, its arguments, and why it was allowed land in the audit journal.

    src/audit/

  15. 15
    Audit + undo → Session store

    Session, usage, and telemetry persist under ~/.harness. The fix is yours to review.

    src/session/store.tssrc/telemetry/logger.ts

Full profile and rationale: Use Cases → Coding assistant.

2. Personal assistant with voice ​

A question gets parked to disk, the server restarts, and the question is still there hours later. That's not an in-memory promise — it's a file.

Personal assistant with voice

A private assistant you talk to. Watch a question get parked to disk, survive a full server restart, and come back hours later through a paired channel.

  1. 1
    Go TUI → WS :7337

    You speak. Streaming STT transcribes; endpointing waits for real silence.

    profiles/assistant.yaml

  2. 2
    Profile registry → Conditional ACL

    mode: assistant applies a tight posture — no shell, no code execution, ever.

    Mode defaults always win over profile-level overrides; they can only tighten, never widen.

    src/profiles/schema.tsprofiles/assistant.yaml

  3. 3
    Built-ins → Deferred asks

    AskUser({ defer: true, ttl: "12h" }) parks the question — written to disk, not held in memory.

    src/tools/builtin/

  4. 4
    Deferred asks

    The connection drops. The server restarts. The question is still there.

    A deferred ask that dies with its connection was never deferred. This one is a file, so it survives.

    src/server/index.tssrc/runs/types.ts

  5. 5
    Channel endpoints → Channels

    Hours later an answer arrives on the paired phone channel.

    inbound: paired — only you can answer. Anyone else who finds the webhook URL is inert.

    src/channels/runtime.tsprofiles/assistant.yaml

  6. 6
    Channels → Deferred asks

    The pending store matches the answer to its parked run and resumes it.

    src/server/undo-handlers.ts

  7. 7
    Temporal + Recall → FS memory

    Recall answers "what was true then" — facts carry validity intervals, not eternal truth.

    Supersession collapses the view without collapsing the history, so the old belief is still auditable.

    src/memory/fs-memory.tsdocs-site/memory.md

  8. 8
    Agent loop → Channels

    The assistant answers back on the same channel it was asked on.

    src/channels/runtime.ts

Full profile and rationale: Use Cases → Personal assistant with voice.

3. Production data-analysis agent ​

Called by code, not a human — so a bad request gets a 422 with a reason instead of a guess, and Bash: deny means exactly that: refused, no prompt, because there's no one to prompt.

Production data-analysis agent

Called by code over REST, not by a person. A bad request gets a 422 rather than a guess, and a denied tool stays denied because there is nobody present to ask.

  1. 1
    Web app → REST /run

    Another service — not a human — POSTs to /run with a dataset path and a question.

    src/server/rest.ts

  2. 2
    REST /run

    A malformed call is missing "question". The contract returns 422 with a reason.

    Fails loudly instead of letting the model guess at missing fields.

    src/profiles/schema.tsprofiles/data.yaml

  3. 3
    REST /run → Session

    A well-formed call validates against the same contract and starts a session.

    src/server/rest.ts

  4. 4
    Session → Autonomy budget

    A budget bounds the run — a caller stuck in a retry loop cannot run up a bill.

    src/runs/budget.ts

  5. 5
    Agent loop → Built-ins

    Read, Grep, and Glob examine the dataset. Those are the only tools it has.

    profiles/data.yaml

  6. 6
    Conditional ACL

    The model tries Bash to reshape the CSV. Bash: deny — refused, with no prompt offered.

    deny is absolute: no mode, no argument, and no yolo flag can widen it. There is also nobody here to prompt.

    src/tools/acl.tsprofiles/data.yaml

  7. 7
    Agent loop → REST /run

    The typed result — answer plus confidence — returns in the shape the contract declared.

    src/profiles/schema.ts

Full profile and rationale: Use Cases → Production data-analysis agent.

4. Unattended ops agent ​

Nobody's watching. Watch the free no-change path run first — the watcher polls, nothing changed, zero cost — before an error spike fires a real run that pages oncall through a conditional ACL and, if it gets stuck, halts on its own budget ceiling rather than running up a bill.

Unattended ops agent

Nobody is watching. The watcher does nothing at all until something actually changes — then one run pages oncall through a conditional ACL and halts itself on a spend ceiling.

  1. 1
    Triggers

    The watch trigger polls the error log. Nothing changed — and nothing happens.

    No model call, no session, no cost. The free no-change path is the whole economic claim of triggers.

    src/triggers/manager.ts

  2. 2
    Triggers → Profile registry

    Errors spike. After a 5s debounce the batch fires a real run — nobody is watching.

    src/triggers/manager.tsprofiles/devops.yaml

  3. 3
    Profile registry → Session

    The devops profile starts an unattended session in production mode.

    profiles/devops.yaml

  4. 4
    Session → Autonomy budget

    A budget opens on the run: $1.00, 40 tools, 300 seconds.

    Checked before every model call and every tool call, not tallied afterwards.

    src/runs/budget.tsprofiles/devops.yaml

  5. 5
    Agent loop → Tool registry

    The agent reads logs and memory pressure, then goes looking for open PRs.

    src/loop/agent-loop.ts

  6. 6
    MCP client → MCP servers

    list_pull_requests is allowed on the GitHub MCP server; everything else on it still prompts.

    MCP tools are namespaced serverName__toolName and carry the server’s own ACL.

    src/mcp/client.tsprofiles/devops.yaml

  7. 7
    Conditional ACL → Channels

    Notify passes a conditional ACL — allowed only because the channel is in trusted_channels.

    allow_if: { arg: channel, in_list: trusted_channels } — a closed, data-only predicate. No code eval, and deny always wins.

    src/tools/acl.tsprofiles/devops.yaml

  8. 8
    Channels → Channel endpoints

    oncall is paged. No other endpoint could have been reached this way.

    src/channels/runtime.ts

  9. 9
    Autonomy budget

    A flaky check keeps retrying. Spend climbs toward the ceiling at 3am.

    src/runs/budget.ts

  10. 10
    Autonomy budget → Channels

    Budget exceeded: cost. The run aborts — a spend ceiling, not a policy refusal.

    BudgetExceeded names the real reason (cost / tools / wall). Partial output is preserved and oncall is told what was in flight.

    src/runs/budget.tssrc/runs/types.ts

  11. 11
    Audit + undo

    Every effectful call is in the journal with why it was allowed — and most can be undone.

    src/audit/src/server/undo-handlers.ts
