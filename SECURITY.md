# Security policy

## Supported versions

Security fixes land on `main`. Use the latest release or current `main` before
reporting an issue.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private
vulnerability reporting for this repository. Include a minimal reproduction,
affected configuration, impact, and any suggested mitigation.

Do not include provider keys, access tokens, private prompts, or user data in a
report. We will acknowledge a valid report, investigate it privately, and
coordinate disclosure after a fix is available.
