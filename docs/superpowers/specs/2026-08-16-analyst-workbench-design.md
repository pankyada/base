## Goal

`mode: analyst` (roadmap #12) promises a sandboxed notebook agent: `ExecuteCode`
in the browser's own Pyodide, no shell, no server-side execution risk. The runtime
half shipped. The surface half did not:

- All nine artifact widgets are placeholder `<div>`s (`web/widgets/GenWidget.tsx:4-12`).
- `ui_render` surfaces are generated by `RenderUI` and never mounted.
- `code_execute` results are forwarded back but never *shown*; the `files` map from
  `ExecutionResult` is discarded (`web/components/HarnessApp.tsx:254-257`).
- There is no way to give the agent data.

An analyst agent that cannot receive a CSV, cannot show a chart, and cannot hand
back a file is a chat window. This design makes the browser the workbench.

### Non-goals

- Not a BI tool. No semantic layer, no scheduled reports, no drill-through.
- Not a real notebook. No cell reordering, no kernel management, no `.ipynb`.
  Cells are a *rendering* of the agent's `ExecuteCode` calls, and the agent owns
  execution order.
- Not a charting library (W0 §4). Eight marks, fixed union.
- Not collaborative. Single operator, single tab.

---

## 1. The three rendering paths

| Path | Producer | Owner of presentation | Use |
|---|---|---|---|
| Widget kit | `artifacts` message, `ArtifactWidget` | client | anything that must be themed, exportable, pinnable |
| Notebook cell | `code_execute` / `code_result` | client | the agent's own computation, shown as work |
| Surface | `ui_render`, `SurfaceSpec` | model | bespoke interactive UI no kind covers |

The kit is the default. Surfaces are the escape hatch. Cells are the audit trail
of how the numbers were produced — the thing that makes an analyst trust output at
all.

## 2. Widget kit

Replaces `web/widgets/GenWidget.tsx` wholesale. Each widget is a pure component:
props in, SVG or semantic HTML out, tokens from
[W0 §5](2026-08-16-web-surface-design.md), no fetching, no global state.

```ts
type ArtifactKind =
  | 'metrics'      // KPI tiles: value, delta, optional sparkline
  | 'bar' | 'line' | 'area' | 'scatter' | 'histogram' | 'heatmap' | 'box'
  | 'table'        // sortable, filterable, CSV export
  | 'correlation'  // matrix, diverging ramp
  | 'diff' | 'filetree' | 'terminal' | 'doc' | 'research'
```

`bar`/`line`/`area`/`scatter` share one data contract so the model can switch mark
without reshaping data:

```ts
interface SeriesData {
  x: { key: string; label?: string; type: 'category' | 'number' | 'time' }
  series: Array<{ key: string; label?: string; unit?: string }>
  rows: Array<Record<string, string | number | null>>
  annotations?: Array<{ x: string | number; label: string }>
}
```

Shared behaviour, implemented once in a `<Plot>` shell rather than per mark:
responsive viewBox, axis ticks with unit-aware formatting, hover crosshair +
tooltip, legend with series toggling, empty state, error state (bad data renders a
diagnostic, never throws), keyboard focus traversal of data points, and an
accessible `<table>` fallback in the a11y tree.

Rules the kit enforces so the model cannot produce a misleading chart:

- Bar charts baseline at zero unless `zeroBaseline: false` is explicit, which draws
  a visible axis-break marker.
- Series colours are assigned from `--series-N` in first-appearance order and are
  stable across a re-render of the same artifact id.
- More than 8 series collapses the tail into "other" with a note.
- `null` is a gap, never zero.

`table` gets its own contract: column types, sort, text filter, column pinning,
row virtualization past 500 rows, and CSV export of the *filtered* view.

Testing: every widget renders from a fixture file with no server
(`web/widgets/__fixtures__/*.json`), including empty, single-point, all-null, huge,
and malformed cases. That fixture set is the regression suite; the current stubs
have none.

## 3. Notebook lane

Each `code_execute` → `code_result` pair becomes a cell card in the conversation,
inline where it happened:

```
┌─ cell 3 · python · 1.2s ───────────────────── ▸ code  ⟳  ⤓ ─┐
│ stdout                                                      │
│ …                                                           │
│ [matplotlib figure]                                         │
│ files: results.csv (14 KB) · plot.png (88 KB)                │
└──────────────────────────────────────────────────────────────┘
```

- Code collapsed by default, expandable, syntax-highlighted.
- `stdout` / `stderr` distinguished; `stderr` and non-zero `exit_code` use
  `--st-error` and stay expanded.
- **Figures.** `ExecutionResult.files` is currently discarded. Image-typed entries
  render inline; everything else becomes a download chip. This is the single
  highest-value fix in the analyst track — matplotlib output is invisible today.
- **Re-run** re-sends the same code as a fresh `ExecuteCode` (a new turn, so the
  agent sees it happened). **Edit-and-run** opens the code in the composer with a
  wrapper prompt rather than silently executing operator-written code as if the
  agent had produced it — provenance stays honest.
- Long stdout truncates with "show all"; a runaway print must not kill the tab.

The Pyodide host (`web/components/HarnessPython.tsx`) needs three fixes for this
to hold: `allowedPackages` is currently passed as `[]` from
`HarnessApp.tsx:375` (so the profile's `executor.allowed_packages` never reaches
the runtime), boot happens lazily on first execute with a visible loading state,
and a worker keeps a long computation off the main thread.

## 4. Surface host

Mounts `ui_render` payloads and answers with `ui_result`.

```
web/surface/SurfaceHost.tsx   # tab host, lifecycle, ui_result reporting
web/surface/frame.html        # the sandboxed document
web/surface/bridge.ts         # postMessage protocol, allowlisted messages
```

- One iframe per surface id; `mode: 'patch'` reuses it and applies only the fields
  sent, `'replace'` remounts.
- Isolation exactly as [W0 §4](2026-08-16-web-surface-design.md): `sandbox="allow-scripts"`
  without `allow-same-origin`, strict CSP, `connect-src 'none'`.
- The bridge exposes only what the tool documents: `emit(name, payload)` back to
  the agent, a shared `state` object, `data`, and `py.run(code)` routed to the same
  Pyodide worker.
- `ui_result` reports `{ ok, errors[], stdout, duration_ms, bytes }`. Uncaught
  errors inside the frame are captured and returned as `errors` so the agent can
  fix its own markup — this feedback channel is why the tool is worth having.
- Timeout: a surface that does not report within 10s gets
  `ok: false, errors: ['render timeout']`, and the frame is torn down.

Escape-attempt tests (parent DOM access, `top.location`, cookie read, `fetch` to
localhost, storage access, form submission) are a permanent corpus that grows and
never shrinks.

## 5. Dataset drawer

Backed by `/datasets` ([W1 §2.8](2026-08-16-web-read-api-design.md)).

- Drag-drop or picker; progress; duplicate-name disambiguation.
- **Schema card** per dataset: rows, columns, and per column — name, dtype, null %,
  distinct count, and a mini distribution (histogram for numeric, top-k bars for
  categorical). This is the artifact that makes an analyst trust the file loaded
  correctly, and it costs one preview request.
- Preview grid, first 50 rows, using the same `table` widget.
- On selection, the drawer injects a short context note into the next message:
  path, shape, and column list — so the agent does not spend a turn discovering
  what it was just handed.
- Uploaded data is provenance-`untrusted`; the drawer displays that state rather
  than hiding it.

## 6. Canvas

A per-project dashboard of pinned artifacts.

- Pin from any artifact, cell figure, or surface. Pinning stores the artifact plus
  its *provenance*: the session, the tool call, and the code that produced it.
- Grid layout, drag to reorder, resize in 1/3 · 1/2 · full column widths.
- **Refresh** re-runs the pinned artifact's generating code against current data
  and replaces the payload in place. A refresh that errors keeps the last good
  render and shows a staleness badge — a dashboard must never silently show
  nothing.
- Export: whole canvas to PNG/PDF, single table to CSV, session to a read-only
  HTML bundle.
- Persistence: canvases are per-project; storage choice is
  [W0 §8 open question 3](2026-08-16-web-surface-design.md).

## 7. Layout

```
┌─ TopBar: profile · project · session · model · cost ──────────────┐
├──────────────┬──────────────────────────────┬────────────────────┤
│ Datasets     │ Conversation                 │ Workspace          │
│  · schema    │  · turns, tool cards         │  [Artifacts]       │
│  · preview   │  · notebook cells            │  [Surfaces]        │
│              │  · stage strip               │  [Canvas]          │
│              │  · composer                  │                    │
├──────────────┴──────────────────────────────┴────────────────────┤
│ StatusBar: context gauge · tokens · cost · connection · mode      │
└───────────────────────────────────────────────────────────────────┘
```

Left drawer and right workspace both collapse; the conversation is the only pane
that never disappears. Below 900 px the layout is single-column with the workspace
as a sheet — the analyst face is desktop-first and says so, rather than pretending
a 400 px chart is useful.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Kit grows into a charting library | Fixed `ArtifactKind` union; new kinds need a design note justifying why `RenderUI` will not do |
| Model produces misleading charts | Zero-baseline default, null-as-gap, series cap, axis-break marker |
| Big datasets kill the tab | Server-side preview/schema; the browser never loads the full file for display; virtualized tables |
| Pyodide boot latency reads as a hang | Lazy boot with visible progress; worker thread; cached wheels |
| Surface escape | Opaque origin + CSP + message allowlist + permanent escape-test corpus |
| Canvas refresh re-runs stale/expensive code | Explicit user action only, never automatic; last-good render retained on failure |
| Edit-and-run launders operator code as agent output | Edited code re-enters as a user message, not a silent execution |

## 9. Open questions

1. Do surfaces get pinned to the canvas, or only fixed widgets? A pinned surface
   cannot be re-themed or exported to CSV, which weakens the canvas contract.
2. Should the dataset drawer auto-profile on upload (one `ExecuteCode` call), or
   stay purely server-sniffed until the analyst asks?
3. Does the notebook lane need a "sessions as notebook" export (`.ipynb`), or is
   the HTML bundle enough?
